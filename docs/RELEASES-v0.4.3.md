## v0.4.3 — إصلاح «invalid argument» + تنظيف قائمة الموديلات

### سبب رفض Google للطلب
كان التطبيق يرسل `thinkingConfig.thinkingBudget = 0` لتسريع الردود.
بعض الموديلات لا تدعم هذا الحقل، فردّت Google: **`Request contains an invalid argument` (400)**.

### الحل: سلّم توافق تلقائي
بدل التخمين، التطبيق يجرّب ثلاثة أشكال للطلب بالترتيب:

| الدرجة | المحتوى |
|---|---|
| 1. كامل | system_instruction + generationConfig |
| 2. بدون تعليمات نظام | تُدمج التعليمات في أول رسالة |
| 3. الحد الأدنى | `contents` فقط |

لو رجع 400 ينزل درجة تلقائيًا. **حُذف `thinkingConfig` نهائيًا** (فحص وحدة يضمن عدم عودته).
كما رُفع `maxOutputTokens` إلى 2048 لأن موديلات التفكير تستهلك رموزًا داخلية.

### قائمة الموديلات
- أُلغيت التكرار: الموديلات الموصى بها تظهر مرة واحدة، والموديلات الأخرى تُعرض تحتها مع عدّاد.
- تُستبعد موديلات الصوت والصور والتضمين وGemma لأنها لا تصلح للمحادثة النصية.

### 20 اختبار وحدة
منها اختبارات تتحقق من شكل جسم الطلب، وغياب `thinkingConfig`، وقراءة SSE، وتصفية الموديلات.
